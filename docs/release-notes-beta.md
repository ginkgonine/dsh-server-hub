# v0.3.0-beta.1 — 远程 Agent Beta

这是测试版，不会替代 GitHub 上的稳定版发布，不发布到 npm。

## 新功能

- 主控 Agent 将一次性任务派到已明确连接的 DSH 实例及允许工作区；远端独立执行，完成后结果自动回到原会话。
- 执行端勾选工作区并保存即可开放，不需要额外密钥、路径或沙箱配置；沿用其现有模型、权限及网页访问许可。
- Hub 标签显示主控/执行端身份和派单连接状态；当前主页面自动作为主控，不需要手动指定角色。
- 主控入口「执行端管理」集中查看已连接执行端与折叠的任务记录；执行端入口「远控设置」只管理该实例的工作区和连接。
- 保留原有实例切换、工作状态、桌面提醒、自定义名称和浏览器标题。

## 修复

- 修正 Cordis 依赖声明，避免等待名为 `required` 的服务。
- 修正异步插件启动的返回值，避免 `Invalid effect` 和远控接口未注册。
- 连接失败显示具体原因，不再只展示 HTTP 400；读取失败显示「连接未知」，不误报未连接。
- 连接/断开后标签立即更新，过期响应不会覆盖新连接状态；不增加高频远控轮询。

## 使用

1. 在主控和执行端安装同一版本，按原方式重启实例并刷新页面。
2. 主控 Hub 选中执行端，打开「远控设置」，选择可执行工作区并保存。
3. 点击「连接执行端」，然后在主控聊天中下达任务。已配置的连接和工作区无需因本次升级重新配置。

远程 Agent 需要 DSH 0.2 的 Web 实例；第一版支持根路径 loopback 入口及本地 SSH 转发，两端浏览器主机名应一致。详细步骤见 [远程 Agent 指南](<remote-agents.md>)。

## 验证与边界

- 197 项自动化测试通过，包括实际 Cordis 激活及 DSH 原生网页授权的跨端口接入测试。
- 已完成同机双实例的服务器只读巡检、结果回传及明确指定容器停止实测。
- 跨服务器、长时间断线等环境仍需实际部署验收；不承诺训练托管或外部进程监督。
- 接入和保存设置不会自动派任务。中断 Agent 不等于停止它已启动的容器或后台进程；远端审批仍由用户处理。
- 旧 `remote_task_*` 方案仅作历史源码/回归保留，不进入本版本发布包或默认 bundle。
