# 远程子 Agent：只需勾选和连接

适用于 DSH 0.2 的 Web 实例；先在主控和远程安装同一个插件版本。可以是同机 `3080 → 3081`，也可以是主控机器上 SSH 隧道映射的端口。

## 第一次使用

以主控 `3080`、远程 `3081` 为例：

1. 在 **3080 的 Hub 上方选中「远程 · 3081」**，点击 **远控设置**。面板显示 **远程 :3081 接受主控 :3080 的任务**。
2. 点击 **选择可执行工作区**，在 3081 弹出的窗口里勾选并 **保存工作区**。保存即开放，无需再找“启用”开关；取消全部勾选并保存即可关闭。
3. 保存后自动返回面板，点击 **连接远程 :3081**。标签会显示“已连接”，然后回到主控聊天，说：**“让 3081 检查当前服务器内存、CPU 和 Docker 状态，不要修改任何东西。”**

主控就是当前打开的主页面实例，无需另外指定。切换 Hub 标签只是在选择要查看/设置的远程，不会切换主控。标签直接显示「主控 · 3080」「远程 · 3081 · 已连接/未连接」，自定义名称仍保留。

选中 3080 自己时，按钮叫 **远程管理**，只展示已连接的远程、工作区与折叠的任务记录。选中 3081 时，按钮叫 **远控设置**，只展示它的连接状态、允许工作区与连接/断开操作。已连接后可点「修改工作区」；不再默认展示登录说明，也不再放一个独立的「主控」返回按钮。

连接状态在页面加载时读取一次，连接/断开后立即更新；手动刷新或打开设置也会重新读取，不额外高频轮询。读取失败显示“连接未知”，不误报“未连接”。“已连接”表示已有派单连接，并不保证远程始终在线；运行状态另行显示。工作区列表来自连接记录，派任务前会重新校验远程的最新许可。连接本身不会派任务或创建普通聊天。

“访问许可”是 DSH 原生网页访问授权，不是另外注册账号：已能打开并使用远程网页时一般已经有了。只有明确提示许可缺失/过期时，才需用该实例启动终端打印的完整网页地址重新打开一次，再手动接入。没有密钥、路径或 YAML 要手填。

两端用同一个浏览器主机名打开：例如都用 `127.0.0.1`，不要一边 `localhost` 一边 `127.0.0.1`。Hub 会在本地页面中统一 iframe 主机名。第一版远控连接支持根路径的 loopback 端口；非本地主机或代理子路径页面请改用本地隧道入口。已有 Hub 的其他切换功能不受此限制。

## 移除 Hub 条目

选中远程标签，点击「命名」旁的 **移除** 并确认，可从当前浏览器的标签栏隐藏该端口。手动记录会移除，自动扫描也不会使它重新出现；已有名称会保留。重新输入同一端口并点击 **+** 即可恢复。主控本机不能移除。

此操作不停止 DSH、不终止任务，也不删除远控连接。Agent 仍可查询已连接的远程；如果希望取消后续派单连接，请在 **远程管理** 中点击 **断开**。

## 名称与回复方式

在 Hub 选中远程并点击「命名」，自定义名称会保存到已连接记录，Agent 查询目标时也能看到名称。尚未连接的实例在连接时同步；已有浏览器名称在打开主控页面时自动迁移，不覆盖服务器已经保存的名称。重名时，Agent 应确认具体目标后再派单。

主控会话的动态上下文会列出已连接实例的数量和名称，并提示用 `remote_agent_targets` 查询目标和工作区，再通过 `remote_agent` 派发任务。没有连接时不注入；连接、断开、改名后在下一次模型请求更新。未命名实例显示其入口地址。生成上下文只读取本地连接信息，不探测远端，也不创建任务。

主控 **远程管理 → 单轮回复（等待远程结果）**：

- 默认关闭：后台派出，远程完成后再唤醒主控回报。
- 开启后：新任务等待远程结果，通过工具返回值交给主控，在当前一轮中回复。若中途需要审批／提问，先把请求交回主控处理，最终结果转为后台回报。
- 切换立即保存，对此主控的所有新任务生效，不自动判断消息来源；已派出的任务保留原回复方式。
- 等待期间不空转调用模型，但长任务、断线和等待审批仍受消息入口或工具调用的超时限制。

## 远程提问与审批

远程提出问题或申请权限时，不必再切到远程聊天寻找任务：

流程只有一条：**远程需要审批／提问 → 告诉原主控 Agent → 主控在聊天里说明并询问用户 → 回传决定，原任务继续。**

- 主控可以正常回复询问，也可以使用 `ask_user_question`；全程在原聊天完成，无需打开 Hub。
- 权限请求包含工具与原因。主控按用户授权，用 `remote_agent_respond` 回传 `outcome: "allowed-once"`（允许一次）、`"rejected"`（拒绝）或 `"cancelled"`（取消）。普通问题和计划审核使用 `answers`。
- 前台等待时，只要远端需要回复，工具就先把请求返回主控，避免主控也卡在等待中；该任务随后按后台方式回报最终结果。
- 已移除强制 GUI 审批、专用网页卡片和 `requiresHuman` 限制。旧记录中的该字段只作兼容读取，不再阻止主控 Agent 回传决定。
- 回复始终匹配原任务和原请求；Hub 只保留连接设置与任务记录。

## 工作方式

- `remote_agent_targets` 列出已经明确连接的实例、自定义名称和允许的工作区；实际派单仍使用唯一的目标 ID。
- `remote_agent` 指定目标、工作区、任务说明。单轮回复关闭时默认后台运行；开启时新任务强制等待结果，不能被模型传入的后台参数绕过。无需反复查询。
- `remote_agent_status` 只读缓存及待处理请求；`remote_agent_respond` 回答普通问题、计划审核或权限请求；`remote_agent_interrupt` 请求中断这个远端 Agent。
- 插件注册 DSH 的 **one-shot subagent provider**，不复制主控聊天历史、模型凭据或权限；远端沿用自己的模型和权限设置。
- 执行发生在一个独立的普通远端会话，方便使用 DSH 原有授权/提问界面。会话终结后自动归档；不删除日志，不把中间工具输出搬进父对话。
- 远程运行不伪装成本地子 Agent，不自动出现在原生 `list_agents`/本地子 Agent 树中；Hub 的远控任务记录与 `remote_agent_status` 提供追踪。
- 完成状态表示 Agent 本轮结束，不等于训练、后台进程或业务一定成功。结果保留错误/中断/输出上限状态。

## 需要知道的四件事

- **授权**：远端仍使用自己的沙箱策略；需要升级时把请求交给主控 Agent，在原聊天中按用户意见处理。主控可以直接回传允许、拒绝或取消。
- **断线**：显示连接中断，不自动换任务 ID 重派。网页访问许可过期时重新打开启动终端打印的完整地址，再手动接入。取消工作区许可会拒绝新任务，但不会擅自杀掉正在执行的任务。
- **重启**：主控恢复对原任务的观察与未投递报告；远程重启后未结束的任务标记中断，不回放模型或 shell。提交响应不确定时保留原 ID，不自动重派。
- **中断**：中断 Agent 不代表训练进程、容器或 `nohup` 已停止。第一版仅支持普通主控会话派出任务，不支持子 Agent 再派远程 Agent、持续续聊或长训练托管。

连接只保存 DSH 原生登录凭据到其私有凭据服务，不交给模型或浏览器 JavaScript。凭据属于同一用户的操作员登录，**不是多用户权限隔离**。断开按钮删除插件保存的连接；不会吊销 DSH 原有登录，也不会停止已有任务。

## 安装与验收

```bash
npm run check
dsh plugin --profile web add .
```

这次审批简化需要主控和远程都更新插件并重启；只更新主控时，旧远端仍可能按原来的人工标志拒绝回复。先用短任务检查「远程申请 → 主控聊天收到通知 → 回传允许／拒绝 → 原任务继续」。自动化 HTTP/SSE 测试使用 Agent/模型服务 fixture，不等于真实模型或服务器验收。

## 接入失败 HTTP 400

新版面板会显示具体错误原因，不再只显示 HTTP 400。旧 UI 将“启用远控”与“勾选工作区”拆成两个开关，只勾选保存可能仍未启用；新版勾选并保存即启用。

- `REMOTE_DISABLED` / `REMOTE_WORKSPACES_EMPTY`：远程尚未开放工作区，请重新勾选并保存。
- `REMOTE_LOGIN_REQUIRED`：浏览器缺少有效的远程网页访问许可；用远程终端打印的完整地址打开一次。
- `REMOTE_HOSTNAME`：两端主机名不同，统一使用 `localhost` 或 `127.0.0.1`。
- `REMOTE_STORAGE`：主控无法写入自己的 DSH 私有凭据存储。

连接失败不会自动重试、派任务或创建会话。旧界面仅有 HTTP 状态码时，无法据此断言是哪一种原因。

## 启动提示 pending / 按钮 HTTP 404

如果启动显示 `dsh-server-hub-remote ... pending (waiting for service: required)`，远控后端没有激活，按钮请求就会返回 404。这不是没勾选工作区或没有登录，也不需要你新增名为 `required` 的服务。

旧实现误用了 `{ required: [...] }` 依赖声明；Cordis 4 需要直接的服务名数组/映射。修正版也修正了异步 `apply` 的返回值，避免随后出现 `Invalid effect`。源码、`lib/remote` 和默认 bundle 必须同步更新。

本地链接安装时，在插件项目执行 `npm run check`，然后按原方式重启 **主控与远程** 并刷新两端页面。仅刷新浏览器不能清除后端进程缓存的旧模块；无需重新配工作区、添加密钥或修改其他插件。若仍报错，查看启动时该条目的具体缺失服务/异常。

匿名访问接口的 401 不能证明远控后端正常：DSH 自身也会对未注册的 `/api` 路径先检查认证。验收需在已经登录的页面打开远控配置/目标列表。

旧的 `remote_task_*`、手填 token/preset、持久训练执行器不再进入本版本发布包或默认 bundle。旧源码保留用于历史回归，不应与新的 `remote_agent_*` 同时启用。
